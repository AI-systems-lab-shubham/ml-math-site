Trace

One number from adding the diagonal, with a surprising rule about products.

01 Meaning

Take a square table of numbers and walk down it from the top left corner to the bottom right. The entries you step on are the diagonal. Add them up and you have the trace of the square matrix. Nothing else is needed: the entries off the diagonal do not count at all.

We write the trace of A as tr(A). The entry in row i and column i is aii, and the trace adds those for every i.

tr(A) = a₁₁ + a₂₂ + … + aₙₙ

03 Real life

The trace has no single physical picture; it is a bookkeeping total. It shows up wherever a table has a natural “same row and column” diagonal:

  • A table of how many people moved between three towns, with “from” down the side and “to” along the top. The diagonal counts the people who stayed where they were, so the trace is the total who stayed.
  • A grid of true labels down the side against guessed labels along the top. The diagonal holds the correct guesses, so the trace is how many were right.
  • A table counting how often each letter is followed by each letter in a text, with the first letter down the side. The diagonal counts doubled letters such as “ll” and “ee”.

Recognition rule. If you want the total of a table’s “same row, same column” entries, it is a trace.

04 Worked example

05 Why and when

The trace squeezes a whole table into one number that behaves nicely: it adds (tr(A + B) = tr(A) + tr(B)), it scales (tr(cA) = c tr(A)), and it ignores the order of a product: tr(AB) = tr(BA). That last rule is surprising, because AB and BA are usually different matrices, as the worked example showed. It extends to three matrices, but only by moving the last one to the front: tr(ABC) = tr(CAB) = tr(BCA), while swapping two neighbours can change the answer.

When it does not fit. The trace throws away everything off the diagonal, so very different matrices can share a trace, and it can be negative or zero, so it is not a measure of size. For size, use the sum of squared entries: tr(ATA) = … for the matrix in the worked example, which is the squared Frobenius norm.

06 How to arrive at it

◆ Motivated

  1. The wish. A single number from a square table that adds when tables add, scales when they scale, and does not change if we multiply two tables in the other order.
  2. The candidates. The product of the diagonal does not add. The largest entry does not add either. The sum of the diagonal does add and scale.
  3. The test. tr(AB) = Σi Σj aijbji, and tr(BA) = Σi Σj bijaji: the same terms with the names i and j swapped. So the order does not matter.
  4. The choice. The sum of the diagonal is a good fit among several. This is a motivated choice, not a forced one, and we have not shown that it is the only one.

07 In an LLM

  • Conceptual link: the squared size of a weight matrix. Weight decay penalises the squared L2 norm of the weights (see the Norms card), and for a weight matrix W that sum of squared entries is tr(WTW). That is an identity about numbers; it does not say how any model is trained beyond what the Norms card states.
  • There is no specific, documented step of a language model that we can point to as a trace.

Simplified. The identity holds for any matrix. It is a different way to write a sum, not a claim about a particular model.

Teach it

Everyday analogy

The total on the main diagonal of a seating chart where each person’s row and column share a number. Where it breaks down: a real table has a meaning for each cell, but the trace just adds the diagonal whatever it means.

Common misconception

“The trace measures how big a matrix is.” It can be negative or zero for a big matrix, because it adds signed diagonal entries and ignores the rest.
